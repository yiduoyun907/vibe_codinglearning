## 一句话理解

**日志不是流水账，而是把「这次为什么这样做、哪里出了问题、下次怎么改」留下来。**

## 记录什么

- **决策**：为什么这样做，放弃了什么。
- **事故**：哪里出了问题，根因是什么。
- **变化**：我的判断和做法发生了什么改变。

## 模板

```markdown
# YYYY-MM-DD · <主题>

## 今天做了什么
- 

## 关键决策
- 决定：
- 原因：
- 放弃了什么：

## 遇到的问题
- 现象：
- 根因：
- 处理：

## 下次改进
- 
```

## 2026-10-18 · 建立学习站

### 今天做了什么

- 确定平台形态：GitHub 仓库作为唯一内容源，VitePress 构建静态站。
- 搭建站点骨架：首页、学习路线、课程、实验、项目、反模式、日志、资源。
- 完成首批 11 节课程与 4 个实验的初稿。
- 加入学习进度、中文搜索、暗色模式和 GitHub Pages 部署配置。

### 关键决策

- **决定**：内容以 Markdown 存放在 Git 仓库，不用语雀作为主存储。
- **原因**：需要版本控制、批量维护和自定义学习功能；语雀更适合作为后续的移动阅读端。
- **放弃了什么**：放弃语雀开箱即用的编辑体验，换取内容所有权和可维护性。

- **决定**：先服务个人使用，内容成熟后再公开。
- **原因**：个人场景允许快速迭代和记录真实失败，不必为了对外可读性牺牲速度。

### 遇到的问题

- 中文全文搜索的分词效果需要验证。当前采用单字 + 二元组切分，后续用真实查询测试召回和精度。
- 学习进度保存在 localStorage，换浏览器或清理缓存会丢失。这是有意的取舍：不引入账号和后端。

### 下次改进

- 完成实验 01，验证「计划 → 修改 → 验收 → 提交」的闭环。
- 用真实项目测试 CLAUDE.md 的效果，而不是只停留在模板。
- 记录第一次 AI 引入的静默副作用，补进[反模式库](/anti-patterns/)。

## 2026-10-18 · 改版：面向零基础

### 今天做了什么

- 明确平台定位：面向完全没有编程经验的学习者。
- 新增[零基础开始](/start/)页，说明准备事项、学习顺序和三个安全习惯。
- 新增三份[术语附录](/appendix/)，覆盖编程基础、AI 协作、工程与安全。
- 重写首页、学习路线、课程总览和 11 节课，增加「一句话理解」「卡住了怎么办」「本课术语」。
- 重写实验、项目和反模式页，减少术语密度，补充可照做的步骤。

### 关键决策

- **决定**：用生活化的比方先建立直觉，再给「准确地说」。
- **原因**：零基础读者需要先理解「它大概是什么」，才能接受精确但抽象的定义。两者同时保留，避免为了易懂而牺牲准确性。
- **放弃了什么**：放弃了一部分简洁性，页面变长，但换来了更低的入门门槛。

- **决定**：术语独立成附录，不在正文里反复展开。
- **原因**：同一个词会在多课出现，集中解释便于查询和维护；正文只在第一次出现时给出简短说明和链接。
- **放弃了什么**：读者需要多跳一次页面，但避免了每课重复解释。

### 遇到的问题

- 把「重要概念」讲简单，很容易滑向「讲错」。解决办法是每个词都保留「准确地说」和「常见误解」两段。
- 零基础的难点不只在术语，还在「不知道下一步做什么」。因此路线里增加了第 0 阶段和明确的过关标准。

### 下次改进

- 找一个真正的零基础读者，观察他在哪一页停下来、查了哪些词。
- 根据真实卡点调整顺序，而不是继续凭感觉加内容。
- 把新出现的术语补进附录，保持正文与附录一致。

## 2026-10-18 · 完成阶段一

### 今天做了什么

- 阶段一从 3 课拆成 4 课，新增「风险与责任」。
- 为四课加入折叠证据卡：Karpathy、Simon Willison、DORA、Copilot RCT、METR、Stack Overflow、OWASP、NIST、Anthropic Docs。
- 新增[内容依据](/appendix/evidence)附录，说明证据等级、主张与证据对照，以及两个生产力研究为什么不矛盾。
- 新增术语：代码审查、规格、Agentic Engineering、提示注入、过度代理、沙箱、敏感信息泄露。
- 课程总数从 11 变为 12，路线、首页和进度统计同步更新。

### 关键决策

- **决定**：证据卡默认折叠，正文只留一句结论。
- **原因**：零基础读者先看懂主线，想核对时再展开；避免把课程变成文献综述。
- **放弃了什么**：部分即时可见的权威感，换取更低的阅读门槛。

- **决定**：不回避相互矛盾的生产力研究。
- **原因**：Copilot RCT 和 METR 研究的是不同任务、不同人群、不同代码库；并列呈现比选边更能训练判断力。

### 遇到的问题

- 证据卡容易变成「炫技」。控制标准：每课最多 2–4 张，每张只回答「来源、结论、边界、对本站含义」。
- 零基础读者可能不会主动展开证据卡。处理方式：正文保留一句可读的结论，证据卡作为可选深度。

### 下次改进

- 用真实零基础读者测试四课的阅读时长和卡点。
- 记录哪些证据卡被展开、哪些术语仍被反复查询。
- 根据真实反馈决定是否调整四课顺序。

:::
