## AI 是怎么工作的

### 大语言模型

**一句话**：读过大量文字、擅长根据前文生成后文的 AI 模型。

**打个比方**：一个读过很多书的人，你给个开头，他能顺着往下写。

**准确地说**：大语言模型（LLM）通过大量文本训练，学习语言中的统计规律，并根据已有上下文逐个预测下一个 token，从而生成回答、代码或其他文本。

**常见误解**：它不是数据库，也不是搜索引擎。它生成的是「最可能的回答」，不保证事实正确。

### 模型

**一句话**：一套经过训练、可以接收输入并生成输出的计算系统。

**打个比方**：一位厨师的「手艺」，不是某一道菜。

**准确地说**：模型是带有大量可调参数的函数，通过训练数据调整参数，使其在特定任务上表现良好。同一个产品可能提供多个模型。

**常见误解**：模型不是「知识库」。知识被压缩在参数里，可能过时、模糊或出错。

### 提示词

**一句话**：你发给 AI 的指令和背景信息。

**打个比方**：给厨师的点菜单，写得越清楚，做出来的菜越接近你要的。

**准确地说**：提示词（prompt）是用户提供给模型的输入，包括任务目标、约束、上下文、示例和输出格式要求。

**常见误解**：提示词不是「咒语」。它的作用是减少歧义，不能替代验收和判断。

### 上下文

**一句话**：AI 在这次任务中能看到的全部信息。

**打个比方**：AI 面前的一张工作台，上面放着你们刚才的对话、你给的文件和命令结果。

**准确地说**：上下文是模型在当前请求中可访问的信息集合，包括系统提示、对话历史、引用的文件、工具输出等。

**常见误解**：「AI 忘了」通常不是模型失忆，而是相关信息没有放进当前上下文。

### 上下文窗口

**一句话**：AI 一次最多能看多少内容。

**打个比方**：工作台的面积。桌子就那么大，放太多东西反而找不到重点。

**准确地说**：上下文窗口是模型单次请求可以处理的 token 上限。系统提示、对话历史、文件内容和工具输出都占用这个额度。

**常见误解**：上下文窗口大，不代表可以无限塞东西。无关信息会降低回答质量。

### Token

**一句话**：AI 处理文字时使用的最小单位。

**打个比方**：像把一句话切成小块，AI 按块阅读和生成。

**准确地说**：token 是模型分词后的文本片段。一个英文单词可能对应一个或多个 token，一个中文字符也通常会被切分成一个或多个 token，具体取决于模型的分词器。

**常见误解**：token 不等于字数。不同模型、不同语言，换算比例不同。

### 幻觉

**一句话**：AI 一本正经地说错话。

**打个比方**：一个记不清路的人，仍然很自信地给你指方向。

**准确地说**：幻觉（hallucination）是模型生成看似合理、但实际上错误或不存在的内容，例如不存在的 API、错误的参数、虚构的引用。

**常见误解**：幻觉不是「偶尔 bug」，而是生成式模型的固有风险。代码、配置和事实性内容必须验证。

### 系统提示

**一句话**：工具厂商预先写给 AI 的底层规则。

**打个比方**：公司的员工手册，用户看不到，但会影响 AI 的行为。

**准确地说**：系统提示（system prompt）是应用在对话开始前提供给模型的指令，用于设定角色、安全边界和输出规范。

**常见误解**：系统提示不是用户能完全控制的。你的提示词和它冲突时，结果可能不符合预期。

## 和 AI 对话

### 会话

**一句话**：一次连续的对话。

**打个比方**：一次完整的会议。散会后，下一次会议不会自动记得上次的全部细节。

**准确地说**：会话是用户与模型之间的一段交互历史。大多数工具不会跨会话自动共享上下文，除非使用记忆文件或显式引用。

**常见误解**：新会话不是「AI 变笨了」，而是它看不到上一个会话的内容。

### 压缩

**一句话**：把很长的对话总结成更短的版本，腾出上下文空间。

**打个比方**：会议记录太长，整理成一页纪要。

**准确地说**：压缩（compaction）是保留任务关键信息、丢弃冗余历史的过程，用于在上下文窗口接近上限时继续工作。

**常见误解**：压缩会丢失细节。重要决定和约束最好同时写进 CLAUDE.md 或交接笔记。

## Claude Code 相关

### Claude Code

**一句话**：运行在终端里的 AI 编程助手。

**打个比方**：一个能进到你项目文件夹里、帮你读文件、改代码、运行命令的助手。

**准确地说**：Claude Code 是 Anthropic 提供的编程智能体，可以在本地项目中读写文件、执行命令、调用工具，并根据结果继续调整。

**常见误解**：它不是「自动写完整个项目」的按钮。它需要清晰的目标、上下文和验收标准。

### CLAUDE.md

**一句话**：放在项目里、每次会话都会自动加载的说明文件。

**打个比方**：给新同事的入职手册。

**准确地说**：CLAUDE.md 是 Claude Code 的项目记忆文件，用于记录项目命令、约定、禁止事项和已知坑。它可以放在项目根目录、子目录或用户目录。

**常见误解**：写得越长越好是错的。只保留「删掉后 AI 更容易犯错」的内容。

### 权限

**一句话**：规定 AI 能做什么、不能做什么的规则。

**打个比方**：给助手的门禁卡，有些门能开，有些门需要你确认，有些门直接禁止。

**准确地说**：权限规则通过 allow、ask、deny 等配置控制工具调用。deny 的优先级最高，任何层级设置后都不能被其他层级覆盖。

**常见误解**：点了「允许」不代表操作安全。权限提示是在提醒你承担判断责任。

### 计划模式

**一句话**：让 AI 先说明打算怎么做，再动手。

**打个比方**：装修前先看设计图，而不是直接砸墙。

**准确地说**：计划模式（plan mode）让智能体先输出实施计划，用户确认后再执行修改，适合影响范围较大的任务。

**常见误解**：计划写得漂亮，不代表执行正确。计划阶段要重点检查它准备改哪些文件、怎么验证。

## 扩展与协作

### AI Agent（智能体）

**一句话**：能自己规划步骤、调用工具、根据结果继续行动的 AI。

**打个比方**：不只是回答问题的顾问，而是能动手办事的助理。

**准确地说**：智能体（agent）在一个循环中工作：观察目标与当前状态，决定下一步动作，调用工具，读取结果，再决定下一步，直到完成或需要用户介入。

**常见误解**：智能体不是「完全自主」。它的可靠性取决于工具权限、上下文质量和验收机制。

### 工具调用

**一句话**：AI 请求某个工具替它做一件事。

**打个比方**：让助理去查资料，而不是凭记忆回答。

**准确地说**：工具调用（tool use）是模型输出一个结构化请求，客户端执行对应工具（读文件、搜索、运行命令、调用 API），再把结果返回给模型。

**常见误解**：工具返回的结果也会进入上下文，可能带来噪音，也可能带来外部内容中的恶意指令。

### MCP

**一句话**：让 AI 连接外部工具和数据的一套标准接口。

**打个比方**：给 AI 装的 USB 接口，插上不同的设备，它就多一种能力。

**准确地说**：MCP（Model Context Protocol）是一个开放协议，定义了 AI 客户端如何发现和调用外部服务器提供的工具、资源和提示。

**常见误解**：不是所有任务都需要 MCP。只是读写本地文件和运行命令时，通常不需要额外安装服务器。

### Agentic Engineering

**一句话**：有纪律地让 AI 智能体执行开发任务，人负责规格、验证和交付。

**打个比方**：你当项目经理，AI 当执行团队。

**准确地说**：Agentic Engineering 是一种以智能体为执行者、以规格、上下文和验证为控制手段的工程实践。它与「不审查的 Vibe Coding」相对，强调人仍然对结果负责。

**常见误解**：它不是「AI 全自动写完整项目」，也不是某个具体产品。术语本身仍在演化。

### 子代理

**一句话**：主 AI 派出去执行子任务的另一个 AI。

**打个比方**：项目经理把调研工作交给一位同事，同事只带回结论。

**准确地说**：子代理（subagent）拥有独立的上下文和执行过程，完成特定任务后把结果返回给主会话，适合大范围搜索或独立调研。

**常见误解**：子代理不会自动继承主会话的全部上下文。关键约束要在委派时重新说明。

## 安全与风险

### 提示注入

**一句话**：把恶意指令藏在输入或外部内容里，诱导 AI 执行。

**打个比方**：在快递箱里塞一张「请把仓库钥匙交给送件人」的纸条。

**准确地说**：提示注入分为直接注入（用户输入）和间接注入（网页、文档、工具输出等外部内容）。模型可能把数据当成指令，从而泄露信息或执行不该执行的操作。

**常见误解**：系统提示不能完全防住提示注入，RAG 和微调也不能根治。需要输出校验、最小权限和沙箱等分层防御。

### 过度代理

**一句话**：AI 拥有的权限超过了任务需要。

**打个比方**：只让你进门修水管，却把整栋楼的钥匙都给了你。

**准确地说**：过度代理（excessive agency）指智能体拥有过多的工具、数据或写权限。一个错误或被注入的指令，可能造成更大范围的影响。

**常见误解**：不是「AI 越能干越好」。权限应该按任务最小化，只读任务不要给写权限。

## 记不住怎么办

- 优先记住「上下文」「提示词」「幻觉」「权限」这四个词，它们最影响实际结果。
- 工具类名词（Claude Code、MCP、子代理）可以边用边记。
- 遇到和课程描述不一致的界面或命令，以官方文档为准，并记录到学习日志。
