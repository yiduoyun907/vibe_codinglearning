# 编程与网站基础

## 怎么用这一页

不用背。遇到不懂的词，回到这里查。每个词都按「一句话、打个比方、准确地说、常见误解」来解释。

## 编程是什么

### 代码

**一句话**：写给电脑看的指令。

**打个比方**：像菜谱。你写下步骤，电脑照着做。

**准确地说**：代码是用某种编程语言写成的文本，遵循该语言的语法规则，可以被解释器或编译器转换成电脑能执行的操作。

**常见误解**：代码能运行，不代表逻辑正确。菜谱能照着做出来，也不代表这道菜是你要的味道。

### 程序

**一句话**：一组让电脑完成某件事的代码和数据的集合。

**打个比方**：菜谱是代码，一整套出餐流程是程序。

**准确地说**：程序通常包含代码、数据、配置和运行环境。一个网站、一个手机应用、一个脚本，都可以叫程序。

**常见误解**：程序不等于「很大的软件」。几十行代码的小工具也是程序。

### 变量

**一句话**：给一个值起的名字。

**打个比方**：一个贴了标签的盒子，盒子里可以放数字、文字或其他东西。

**准确地说**：变量是程序中用于存储和引用数据的命名位置。它的值在程序运行过程中可以改变。

**常见误解**：变量不是「随便起的名字」。名字要能说明它装的是什么，否则过几天你自己也看不懂。

### 函数

**一句话**：一段可以重复使用的代码，接收输入，给出结果。

**打个比方**：咖啡机。你放咖啡豆和水（输入），它给你一杯咖啡（输出）。

**准确地说**：函数是一段有名字的代码块，可以接收参数、执行特定任务，并返回一个值。有些函数没有返回值，但会产生副作用，例如写入文件。

**常见误解**：函数不是越长越厉害。好的函数通常只做一件事。

### 参数与返回值

**一句话**：参数是「交给函数的东西」，返回值是「函数交给你的东西」。

**打个比方**：点咖啡时说「少冰、加糖」是参数，拿到的那杯咖啡是返回值。

**准确地说**：参数是调用函数时传入的值；返回值是函数执行结束后返回给调用方的结果。

**常见误解**：不是所有函数都有返回值。有些函数只做事，不交结果。

## 网站是怎么工作的

### 前端

**一句话**：用户在浏览器里看到和操作的部分。

**打个比方**：餐厅的用餐区，你能看到菜单、桌椅和服务员。

**准确地说**：前端是运行在用户设备（通常是浏览器）上的界面层，负责展示内容、处理交互，并通过网络请求后端数据。

**常见误解**：前端不只是「画页面」。它还要处理状态、错误、加载过程和可访问性。

### 后端

**一句话**：用户看不见、负责处理数据和业务规则的部分。

**打个比方**：餐厅的后厨和仓库。

**准确地说**：后端运行在服务器上，负责处理请求、执行业务逻辑、读写数据库，并返回结果。

**常见误解**：不是所有网站都有后端。纯静态网站可以没有后端。

### HTML

**一句话**：网页的骨架和内容。

**打个比方**：房子的墙、门和房间布局。

**准确地说**：HTML（超文本标记语言）用标签描述网页的结构和语义，例如标题、段落、按钮、图片。

**常见误解**：HTML 不是编程语言，它描述结构，不做计算。

### CSS

**一句话**：网页的外观和排版。

**打个比方**：装修、颜色、家具摆放。

**准确地说**：CSS（层叠样式表）控制网页的颜色、字体、间距、布局和响应式表现。

**常见误解**：CSS 不只是「美化」。布局错乱、移动端显示异常，往往也是 CSS 问题。

### JavaScript

**一句话**：让网页「动起来」的编程语言。

**打个比方**：房子里的电灯开关和自动门。

**准确地说**：JavaScript 运行在浏览器（或 Node.js 等环境）中，负责交互、数据处理和网络请求。

**常见误解**：JavaScript 和 Java 没有关系，它们是两种不同的语言。

### 浏览器

**一句话**：你用来打开网页的软件。

**打个比方**：一扇能看到网页世界的窗户。

**准确地说**：浏览器负责向服务器请求网页资源，解析 HTML、CSS，执行 JavaScript，并把结果显示出来。

**常见误解**：浏览器不只是「显示」。它还负责安全隔离、缓存和运行网页程序。

### 服务器

**一句话**：一台持续运行、为别人提供服务的电脑或程序。

**打个比方**：24 小时营业的后厨。

**准确地说**：服务器是网络上提供资源或计算能力的计算机或软件进程。网站、接口、数据库都可以运行在服务器上。

**常见误解**：服务器不一定是「一台单独的机器」。它也可能是云服务中的一个进程或容器。

### 客户端

**一句话**：发起请求、使用服务的一方。

**打个比方**：去餐厅吃饭的顾客。

**准确地说**：客户端是向服务器请求资源或服务的软件，例如浏览器、手机 App、命令行工具。

**常见误解**：客户端不一定是「用户直接操作的界面」。一个程序调用另一个程序的接口时，它也是客户端。

### 数据库

**一句话**：有组织地存放数据的地方。

**打个比方**：带索引的仓库，能快速找到你要的那一箱货。

**准确地说**：数据库是按一定结构组织、可以高效查询和更新的数据集合，通常由数据库管理系统管理。

**常见误解**：数据库不是「一个 Excel 文件」那么简单。它还要处理并发、权限、备份和一致性。

### API

**一句话**：程序之间约定好的「点菜方式」。

**打个比方**：餐厅菜单。你按菜单点菜，后厨按约定做菜，双方不需要知道对方内部怎么工作。

**准确地说**：API（应用程序编程接口）定义了一组规则、函数或网络端点，让一个程序可以请求另一个程序的服务或数据。

**常见误解**：API 不是「一个网站」。它是一份契约，规定你怎么请求、会得到什么。

## 开发环境

### 依赖

**一句话**：你的项目需要用到的外部代码。

**打个比方**：做菜时用到的现成酱料。

**准确地说**：依赖是项目运行或构建时需要的第三方库、框架或工具。它们通常由包管理器安装。

**常见误解**：依赖越多越好是错的。每多一个依赖，就多一份维护和安全风险。

### 包与包管理器

**一句话**：包是别人写好的代码包，包管理器是安装和更新这些包的工具。

**打个比方**：包是超市里的预制食材，包管理器是采购和库存系统。

**准确地说**：包（package）是可分发的代码单元，通常包含版本信息和依赖声明。包管理器（如 npm）负责下载、安装、升级和锁定版本。

**常见误解**：装了很多包，不代表项目更专业。能用现有能力解决，就不要新增依赖。

### 环境

**一句话**：代码运行时所处的条件。

**打个比方**：做菜时的厨房设备、温度和食材。

**准确地说**：环境包括操作系统、运行时版本、依赖版本、环境变量和配置。同一份代码在不同环境中可能表现不同。

**常见误解**：「在我电脑上能跑」不等于「在服务器上能跑」。环境差异是常见故障来源。

### 终端

**一句话**：用文字给电脑下命令的窗口。

**打个比方**：不用点按钮，直接对电脑说话。

**准确地说**：终端是一个文本界面，你输入命令，shell 解释命令并调用相应的程序执行。

**常见误解**：终端不是「只有程序员才会用」。它只是另一种操作方式，常用的命令并不多。

### 命令行

**一句话**：你在终端里输入的那一行行命令。

**打个比方**：给电脑下的简短指令。

**准确地说**：命令行是用户输入的文本指令及其参数，例如 `cd project`、`npm install`。

**常见误解**：命令打错不会「爆炸」，但可能产生意外结果。执行前先看清路径和参数。

### 路径

**一句话**：文件或文件夹在电脑里的位置。

**打个比方**：地址。`C:\Users\你\project` 就是完整地址。

**准确地说**：路径描述文件系统中的位置，分为绝对路径（从根目录开始）和相对路径（从当前目录开始）。

**常见误解**：路径里有空格时通常要加引号，否则命令可能把它拆成两段。

### 端口

**一句话**：一台电脑上某个网络服务的「门牌号」。

**打个比方**：同一栋楼里的不同房间号。

**准确地说**：端口是一个数字，用来区分同一台主机上的不同网络服务。例如 `localhost:8000` 表示本机的 8000 端口。

**常见误解**：端口被占用时，服务启动会失败。换一个端口或关闭旧进程即可。

### localhost

**一句话**：指你自己的电脑。

**打个比方**：「我自己家」，不是外面的地址。

**准确地说**：`localhost` 是一个特殊主机名，通常解析到 `127.0.0.1`，表示本机回环地址，只能从本机访问。

**常见误解**：`localhost` 上能打开，不代表别人也能访问。要让别人访问，需要部署到服务器。

### localStorage

**一句话**：浏览器提供的一个小仓库，可以在用户电脑上保存少量数据。

**打个比方**：浏览器给每个网站的一格抽屉，关上网页再打开，东西还在。

**准确地说**：localStorage 是浏览器提供的键值存储接口，数据以字符串形式保存，按域名隔离，没有过期时间，容量通常为几 MB。

**常见误解**：localStorage 不适合保存敏感数据，也不能跨设备同步。清空浏览器数据会丢失。

## 发布上线

### 静态网站

**一句话**：提前生成好文件、直接交给浏览器显示的网站。

**打个比方**：提前印好的宣传册，谁来都发同一本。

**准确地说**：静态网站由预先构建的 HTML、CSS、JavaScript 和资源文件组成，服务器通常只负责按请求返回文件，不针对每个请求做服务端计算。

**常见误解**：静态网站也能有交互和搜索。本站就是静态网站，搜索是在浏览器里完成的。

### 部署

**一句话**：把做好的网站放到别人能访问的地方。

**打个比方**：把做好的菜端到餐厅前台。

**准确地说**：部署是把构建产物上传到托管平台或服务器，并配置域名、路径和运行环境，使用户可以通过网络访问。

**常见误解**：部署不是「上传一个文件夹」就完事。还要处理子路径、缓存、HTTPS、构建失败等问题。

### URL

**一句话**：网页的地址。

**打个比方**：一本书的页码和位置。

**准确地说**：URL（统一资源定位符）描述资源的位置和访问方式，通常包含协议、域名、路径，可能还有查询参数。

**常见误解**：URL 里的路径区分大小写，也可能带子路径。部署到 GitHub Pages 时，子路径配置错误会导致资源 404。

### 域名

**一句话**：好记的网站名字。

**打个比方**：给一栋楼起的名字，背后对应一个实际地址。

**准确地说**：域名是人类可读的地址，通过 DNS 解析到 IP 地址。域名需要通过注册商购买和配置。

**常见误解**：买了域名不等于网站已经上线。还需要配置解析和托管。

## 记不住怎么办

- 先记住「一句话」和「打个比方」，准确解释在需要时再看。
- 在课程里遇到这些词时，回来查一次，比一次性背十个词有效。
- 查完仍然不懂，把词发给 AI，要求它用零基础能懂的方式解释。
