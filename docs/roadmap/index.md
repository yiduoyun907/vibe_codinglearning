# 学习路线

<LessonMeta level="零基础" minutes="约 5 小时" output="一套能重复使用的 Vibe Coding 工作流" prerequisite="无" />

## 这条路线假设什么

它假设你：

- 没有学过编程；
- 没有用过终端、Git 或 AI 编程工具；
- 每周能投入 5–7 小时；
- 愿意动手，而不是只看不练。

如果上面的描述符合你，按顺序走即可。遇到不懂的词，去[术语附录](/appendix/)查。

## 路线目标

走完前三个阶段后，你应该能够：

- 用大白话解释 Vibe Coding 是什么、能做什么、不能做什么。
- 在自己的电脑上跑通 Claude Code、终端和 Git。
- 把模糊想法拆成 AI 能执行、你能验收的任务。
- 用 Git 保存进度、审查改动、在出错时退回来。
- 独立完成一个小项目，并把它发布到网上。

## 五个阶段

| 阶段 | 主题 | 你需要先完成 | 关键产出 | 过关标准 |
| --- | --- | --- | --- | --- |
| 第 0 阶段 | 准备 | 无 | 装好工具，建好练习目录 | 能打开终端并启动 Claude Code |
| 阶段一 | 认知基础 | 第 0 阶段 | 对 AI 能力边界的判断 | 能说清什么任务适合交给 AI |
| 阶段二 | 工具链 | 阶段一 | Claude Code + 终端 + Git | 能完成一次「描述 → 生成 → 审查 → 提交」 |
| 阶段三 | 提示与规格 | 阶段二 | SPEC 模板与 CLAUDE.md | 能让 AI 按验收标准交付一个中等任务 |
| 阶段四 | 迭代与验证 | 阶段三 | 小步交付与调试能力 | 能把失败定位到提示、上下文、代码或需求 |
| 阶段五 | 工程化与发布 | 阶段四 | 部署与维护能力 | 能让项目在线上稳定运行 |

当前站点覆盖到**阶段三**。阶段四和阶段五会在你完成前三个阶段后，结合实际项目逐步补齐。

## 第 0 阶段：准备

目标：让工具能跑起来，并建立一个安全的练习环境。

1. 读[零基础开始](/start/)，建立三个安全习惯。
2. 安装 Claude Code，运行 `claude --version` 确认安装成功。
3. 创建一个练习目录，例如 `~/vibe-lab`。
4. 打开终端，进入练习目录，启动一次 `claude`，然后退出。

这一阶段不需要写任何代码。**能启动、能退出，就算完成。**

## 每周怎么安排

| 周次 | 内容 | 验收动作 |
| --- | --- | --- |
| 第 0 周 | 准备 + 认知基础 | 在空目录里让 AI 交付一个可运行页面 |
| 第 1 周 | Claude Code + 终端 | 独立完成一次「计划 → 修改 → 验证 → 提交」 |
| 第 2 周 | Git + MCP | 用 Git 记录并回滚一次 AI 改动 |
| 第 3 周 | 需求拆解 + CLAUDE.md | 给一个真实项目补上 CLAUDE.md |
| 第 4 周 | PRD/SPEC + 上下文管理 | 用一个 SPEC 完成一个完整小功能 |

时间不是硬指标。判断能否进入下一阶段，只看一件事：**你能不能独立完成该阶段的验收动作。**

## 毕业标准

完成以下五项，才算真正走完首轮路线：

- [ ] 能用自己的话解释 Vibe Coding 的适用边界与主要风险。
- [ ] 能独立配置 Claude Code，并说明每个权限设置的作用。
- [ ] 能用 Git 审查 AI 的改动，并回滚到任意一次提交。
- [ ] 能写出包含验收标准的 SPEC，让 AI 按规格交付。
- [ ] 有一个真实项目，从需求到部署全程由你主导、AI 执行。

::: warning 不要同时学所有东西
路线按依赖顺序设计。跳过工具链直接学提示词，会在遇到真实代码时失去判断力；跳过规格直接堆功能，会把项目变成不可维护的黑箱。
:::

## 卡住了怎么办

| 情况 | 先做什么 |
| --- | --- |
| 看不懂某个词 | 查[术语附录](/appendix/) |
| 命令报错 | 把完整报错和刚才的操作发给 AI，让它解释 |
| 不知道下一步 | 回到当前课的「验收清单」，看还差哪一项 |
| 项目做不下去了 | 缩小范围，先完成一个能跑的最小版本 |
| 担心弄坏文件 | 停止操作，先用 `git status` 和 `git diff` 确认状态 |
