# 学习路线

<LessonMeta level="全阶段" minutes="约 5 小时" output="一套可复用的 Vibe Coding 工作流" prerequisite="无" />

## 路线目标

完成这条路线后，你应该能够：

- 判断一个需求是否适合交给 AI，以及哪些部分必须自己把关。
- 用 Claude Code 在真实项目中完成从需求到可运行代码的交付。
- 把模糊想法拆成 AI 可执行的规格，并写出稳定的项目上下文。
- 用 Git 管理 AI 产生的改动，能审查、能回滚、能解释。
- 遇到问题时，知道该改提示、改上下文、改代码，还是改需求。

## 四个阶段

| 阶段 | 主题 | 关键产出 | 过关标准 |
| --- | --- | --- | --- |
| 一 | 认知基础 | 对 AI 能力边界的判断框架 | 能说清一个任务为什么适合或不适合交给 AI |
| 二 | 工具链 | Claude Code + 终端 + Git 工作流 | 能独立完成一次「描述需求 → 生成 → 审查 → 提交」 |
| 三 | 提示与规格 | SPEC 模板与 CLAUDE.md | 能让 AI 在一个中等任务上一次通过验收清单 |
| 四 | 迭代与验证 | 小步交付循环 | 能把失败拆解到提示、上下文、代码或需求层 |

当前站点覆盖前三个阶段。第四阶段「迭代与验证」、工程化与发布，会在你完成前三个阶段后逐步补齐。

## 每周怎么安排

建议每周 5–7 小时，按下面的节奏推进：

| 周次 | 内容 | 验收动作 |
| --- | --- | --- |
| 第 1 周 | 阶段一 + Claude Code、终端 | 在空目录里让 AI 交付一个可运行的静态页面 |
| 第 2 周 | Git + MCP | 用 Git 记录并回滚一次 AI 改动 |
| 第 3 周 | 需求拆解 + CLAUDE.md | 给一个真实项目补上 CLAUDE.md |
| 第 4 周 | PRD/SPEC + 上下文管理 | 用一个 SPEC 完成一个完整小功能 |

时间不是硬指标。判断是否进入下一阶段的唯一标准，是你能不能独立完成该阶段的验收动作。

## 毕业标准

完成以下五项，才算真正走完首轮路线：

- [ ] 能用自己的话解释 Vibe Coding 的适用边界与主要风险。
- [ ] 能独立配置 Claude Code，并说明每个权限设置的作用。
- [ ] 能用 Git 审查 AI 的改动，并回滚到任意一次提交。
- [ ] 能写出包含验收标准的 SPEC，让 AI 按规格交付。
- [ ] 有一个真实项目，从需求到部署全程由你主导、AI 执行。

::: warning 不要同时学所有东西
路线按依赖顺序设计。跳过工具链直接学提示词，会在遇到真实代码时失去判断力；跳过规格直接堆功能，会把项目变成不可维护的黑箱。
:::
