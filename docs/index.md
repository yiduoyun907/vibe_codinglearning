## 第一次来，从这里开始

1. **读[零基础开始](/start/)**：了解你需要准备什么，以及三个安全习惯。
2. **按[学习路线](/roadmap/)**：从第 0 阶段开始，一次只学一课。
3. **遇到不懂的词**：去[术语附录](/appendix/)查，不要硬撑。

::: tip 你不需要先学会编程
本站假设你完全没有编程经验。你需要在实践中慢慢学会三件事：把想法说清楚、判断结果对不对、出错时能退回来。
:::

## 你不需要准备什么

- 不需要会写代码。
- 不需要英语很好。
- 不需要数学很好。
- 不需要懂终端、Git、部署这些词。

## 本站怎么保证你看得懂

| 做法 | 目的 |
| --- | --- |
| 先给生活化的比方，再给准确解释 | 先建立直觉，再纠正偏差 |
| 每个重要概念都说明「常见误解」 | 避免把「能跑」当成「正确」 |
| 每课都有动手任务和验收清单 | 用结果判断是否学会，而不是用阅读量 |
| 术语附录按分类和场景组织 | 遇到陌生词能快速查到 |
| 实验和项目都在临时目录进行 | 降低试错成本，保护你的真实文件 |

## 当前覆盖

| 阶段 | 主题 | 你会得到什么 |
| --- | --- | --- |
| 第 0 阶段 | 环境准备 | 知道怎么开始，准备好工具和练习目录 |
| 阶段一 | 认知基础 | 能判断什么任务适合交给 AI，什么必须自己把关 |
| 阶段二 | 工具链 | 跑通 Claude Code、终端与 Git 的最小工作流 |
| 阶段三 | 提示与规格 | 写出可执行的规格和项目上下文 |

首批 11 节课，预计约 5 小时。后续阶段会在实践中逐步补齐。

## 内容原则

- 每课必须有一个可验证的产出。
- 优先记录真实踩坑，而不是搬运二手结论。
- 重要的概念不简化：先用简单的话说清楚，再保留准确的定义和边界。
- 术语解释和课程正文分开维护，方便查漏补缺。
