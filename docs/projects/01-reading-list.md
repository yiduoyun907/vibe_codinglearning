# 项目 01 · 阅读清单

<LessonMeta level="实战" minutes="约 5 小时" prerequisite="完成实验 01–03" output="一个部署后可访问的阅读管理应用" />

## 一句话理解

**做一个你自己会用的阅读清单：记下想读的文章，标记已读，按状态筛选，数据保存在浏览器里。**

## 目标

这个项目故意不引入后端。先把页面、存储、错误处理和部署走通，再考虑服务端。

## 功能范围

包含：

- 添加文章（标题、链接）；
- 标记已读 / 未读；
- 按「全部 / 未读 / 已读」筛选；
- 删除文章；
- 数据保存在 localStorage；
- 手机宽度下可用；
- 部署到静态托管平台。

不包含：

- 用户账号与多设备同步；
- 网页内容抓取；
- 标签体系；
- 批量导入导出。

## 里程碑

| 阶段 | 内容 | 怎么验收 |
| --- | --- | --- |
| M1 | 静态列表 + 添加 | 能添加并显示，空输入被拒绝 |
| M2 | 已读切换 + 筛选 | 三种筛选结果正确，刷新后状态保留 |
| M3 | 删除 + 错误处理 | 删除前有确认；保存失败有提示且状态回滚 |
| M4 | 部署 | 公网地址可访问，手机布局不溢出 |

## SPEC 要点

写 SPEC 时，至少明确这些：

- 数据结构：`id`、`title`、`url`、`read`、`createdAt`；
- 存储键名带版本，例如 `reading-list:v1`；
- 链接要做基本校验，拒绝 `javascript:` 等危险协议；
- 数据损坏时回退为空列表，不阻塞页面；
- 删除前要二次确认；
- 筛选状态可以不做持久化，但可以作为进阶项写进 URL。

## 验收标准

- Given 空输入 When 点击添加 Then 不新增记录，并显示提示
- Given 合法输入 When 添加 Then 列表出现新记录
- Given 未读记录 When 勾选 Then 进入已读状态，筛选结果同步变化
- Given 已读记录 When 刷新页面 Then 状态保持
- Given 保存失败 Then 状态回滚并显示错误
- Given 删除记录 Then 需要确认，取消则不删除
- Given 375px 宽度 Then 页面没有横向滚动

## 交付要求

- 至少 4 个有意义的提交，对应里程碑；
- 一份 `README.md`，说明功能和本地运行方式；
- 一份 `CLAUDE.md`，记录项目约定；
- 一份复盘，包含至少一个真实问题和解决过程；
- 一个可以公开访问的地址。

## 卡住了怎么办

- **功能太多做不完**：先完成 M1 和 M2，删除和筛选可以后补。
- **刷新后数据丢失**：检查 localStorage 的键名和读取时机。
- **删除没有确认**：把「删除前要确认」写进验收标准，再让 AI 修。
- **手机布局溢出**：让 AI 只修 375px 宽度下的溢出，不要同时改功能。
- **部署后样式丢失**：检查构建产物的子路径配置。
