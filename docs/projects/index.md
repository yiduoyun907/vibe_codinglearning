## 一句话理解

**课程教你单个动作，实验让你练单个动作，项目要求你把它们连起来，做成一个别人能打开、能用的小产品。**

## 项目流程

每个项目都按同一套流程推进：

1. **写 SPEC**：范围、流程、数据、验收标准。
2. **建基线**：Git 初始化，提交一个最小可运行版本。
3. **切片实现**：每个切片可验证、可提交、可回滚。
4. **自己验收**：逐条运行验收标准，记录结果。
5. **部署上线**：让项目离开本地，接受真实环境检验。
6. **写复盘**：记录偏差、事故和下次改法。

::: warning 项目不是教程复刻
不要照着步骤原样复制。每个项目至少做一次自己的取舍：改一个需求、换一种存储方式、加一个错误场景。只有你做过决定，项目才算你的。
:::

## 卡住了怎么办

- **不知道先做哪一步**：先做「能显示假数据」的最小版本。
- **功能越做越多**：回到 SPEC 的「不包含」，把新想法记下来，不要当场加。
- **部署失败**：先检查构建是否通过，再检查子路径和仓库设置。
- **做不下去了**：缩小范围，先交付一个能跑的核心版本。
