# 实验 03 · 从 SPEC 到代码

<LessonMeta level="进阶" minutes="60" prerequisite="PRD 与 SPEC、需求拆解" output="一份 SPEC、三个提交、一份验收记录" />

## 目标

用一份 SPEC 驱动 AI 分片实现，验证「规格质量决定交付质量」。

## 实验任务

实现「阅读清单的已读标记」，可以直接使用[PRD 与 SPEC](/guide/spec/prd-spec) 中的示例规格，也可以换成你自己的一个小功能。

要求：

- 不引入框架；
- 使用 localStorage；
- 每条记录包含 id、title、url、read；
- 页面移动端可用。

## 步骤

### 1. 准备规格

如果使用示例规格，先通读一遍，确认：

- 范围里有「不包含」；
- 验收标准覆盖主路径、边界和错误；
- 数据模型明确。

### 2. 建立基线

```bash
mkdir -p ~/vibe-lab/reading-list
cd ~/vibe-lab/reading-list
git init
```

创建最小页面和假数据，提交基线。

### 3. 分三个切片实现

每次只做一个切片，验收通过后再进入下一个：

| 切片 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 渲染静态列表和复选框 | 三条假数据正确显示，未读状态正确 |
| 2 | 点击切换已读状态（仅内存） | 勾选和取消都正确，刷新后不保留 |
| 3 | 写入 localStorage，处理写入失败和数据损坏 | 刷新后保留；模拟失败时状态回滚 |

每个切片完成后：

```bash
git diff
git add .
git commit -m "feat: <切片说明>"
```

### 4. 记录偏离

实现过程中，AI 可能偏离规格。记录：

- 偏离了什么；
- 你为什么接受或拒绝；
- 是否更新了 SPEC。

### 5. 最终验收

逐条对照 SPEC 的验收标准，记录结果。至少手动模拟一次存储失败（可以在浏览器控制台临时覆盖 `localStorage.setItem`）。

## 验收清单

- [ ] 三个切片分别提交，且每个提交可独立回滚。
- [ ] SPEC 中的验收标准逐条有结果记录。
- [ ] 至少模拟并验证了一种错误路径。
- [ ] 记录了一处 AI 偏离规格的地方及处理方式。
- [ ] 最终代码没有引入额外依赖。

## 复盘问题

- 哪个切片最容易出现「看起来对但没验证」？
- 如果没有 SPEC，AI 会自行补上哪些你没写的假设？
- 下次写 SPEC 时，你会优先补哪一类信息？
