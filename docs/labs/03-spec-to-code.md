# 实验 03 · 从 SPEC 到代码

<LessonMeta level="进阶" minutes="60" prerequisite="PRD 与 SPEC、需求拆解" output="一份 SPEC、三个提交、一份验收记录" />

## 一句话理解

**这一次，你不是直接说「帮我做个功能」，而是先写一份菜谱，再让 AI 照着菜谱分三次做。**

## 目标

实现「阅读清单的已读标记」。可以直接使用[PRD 与 SPEC](/guide/spec/prd-spec) 里的示例，也可以换成你自己的一个小功能。

要求：

- 不引入框架；
- 使用 localStorage；
- 每条记录包含 id、title、url、read；
- 手机宽度下可用。

## 开始前检查

- [ ] 已经完成实验 01，知道怎么启动本地页面。
- [ ] 已经会用 `git add` 和 `git commit`。
- [ ] 准备好一份 SPEC，或者打算用课程里的示例。

## 步骤

### 第 1 步：准备 SPEC

如果使用示例 SPEC，先通读一遍，确认：

- 范围里有「不包含」；
- 验收标准覆盖主路径、边界和错误；
- 数据模型明确。

### 第 2 步：建立基线

```bash
mkdir -p ~/vibe-lab/reading-list
cd ~/vibe-lab/reading-list
git init
```

创建最小页面和三条假数据，提交一次基线。

### 第 3 步：分三个切片实现

每次只做一个切片，验收通过后再进入下一个：

| 切片 | 做什么 | 怎么验收 |
| --- | --- | --- |
| 1 | 显示静态列表和复选框 | 三条假数据正确显示，未读状态正确 |
| 2 | 点击切换已读状态（只在内存里） | 勾选和取消都正确，刷新后不保留 |
| 3 | 保存到 localStorage，处理保存失败和数据损坏 | 刷新后保留；模拟失败时状态回滚 |

每个切片完成后：

```bash
git diff
git add .
git commit -m "feat: <切片说明>"
```

### 第 4 步：记录偏离

实现过程中，AI 可能偏离 SPEC。记录：

- 偏离了什么；
- 你为什么接受或拒绝；
- 是否更新了 SPEC。

### 第 5 步：最终验收

逐条对照 SPEC 的验收标准，记录结果。

至少手动模拟一次保存失败：可以在浏览器控制台临时让 `localStorage.setItem` 报错，观察页面是否回滚并提示。

## 验收清单

- [ ] 三个切片分别提交，每个提交都能单独回滚。
- [ ] SPEC 中的验收标准逐条有结果记录。
- [ ] 至少模拟并验证了一种错误路径。
- [ ] 记录了一处 AI 偏离规格的地方及处理方式。
- [ ] 最终代码没有引入额外依赖。

## 卡住了怎么办

- **不知道切片怎么分**：先做「显示假数据」，再做「能点」，最后做「能保存」。
- **不知道错误路径怎么测**：在浏览器控制台里让保存函数报错，观察页面反应。
- **AI 一次做了三个切片**：让它停下，先回滚，再按切片重新来。
- **验收标准太多**：先完成前三条主路径，再补边界和错误。

## 复盘问题

- 哪个切片最容易出现「看起来对但没验证」？
- 如果没有 SPEC，AI 会自行补上哪些你没写的假设？
- 下次写 SPEC 时，你会优先补哪一类信息？
