# 实验 01 · 第一次交付

<LessonMeta level="入门" minutes="45" prerequisite="Claude Code 实操、Git 最小必要技能" output="一个可运行页面、一次提交、一条实验记录" />

## 目标

在空目录里，让 AI 完成一次从需求到可验证结果的完整交付。你要亲历五个环节：基线、规格、计划、执行、验收。

## 准备

- 已安装 Node.js、Git、Claude Code；
- 一个可以随意折腾的临时目录；
- 不需要任何框架和依赖。

## 实验任务

做一个「今日待办」单页应用：

- 可以添加待办事项；
- 可以勾选完成；
- 可以删除事项；
- 数据保存在 localStorage，刷新后保留；
- 移动端可用。

## 步骤

### 1. 建立基线

```bash
mkdir -p ~/vibe-lab/todo-app
cd ~/vibe-lab/todo-app
git init
```

创建 `README.md`，写一句项目说明，然后提交：

```bash
git add README.md
git commit -m "chore: initial baseline"
```

### 2. 写验收标准

先把「完成」写清楚，再交给 AI：

```text
验收标准：
1. 输入内容后点击添加，列表新增一条，输入框清空
2. 空内容不能添加
3. 勾选后条目显示完成样式，再次点击可取消
4. 点击删除后条目消失
5. 刷新页面后，列表和完成状态保持不变
6. 页面宽度 375px 时布局不溢出
```

### 3. 让 AI 先给计划

启动 `claude`，把需求和验收标准一起给它，并要求：

> 先不要写代码。说明你会创建哪些文件、分几步实现、每一步怎么验证。

检查计划是否覆盖：

- 数据结构和存储键名；
- 添加、勾选、删除三个行为；
- 空输入和存储失败的错误处理；
- 如何验证刷新后的持久化。

计划不合理就先改计划，不要急着让它写。

### 4. 分步执行

建议拆成三个提交：

1. 静态页面与列表渲染；
2. 添加、勾选、删除；
3. localStorage 持久化与错误处理。

每完成一步，自己运行并对照验收标准。

### 5. 独立验收

逐条检查六条验收标准。不要只听 AI 说「已完成」。

### 6. 提交与记录

```bash
git add .
git commit -m "feat: complete todo app"
git log --oneline
```

把过程写进[学习日志](/log/)。

## 验收清单

- [ ] 六条验收标准全部通过。
- [ ] 至少有两个提交，每个提交对应一个可验证的阶段。
- [ ] 能说清 `git diff` 中每一处主要改动的作用。
- [ ] 实验记录包含「卡住的地方」和「下次改进」。
- [ ] 实验目录之外没有产生副作用。

## 复盘问题

- 你在哪一步最想跳过验收？为什么？
- AI 的计划和你预期的一致吗？不一致时谁更合理？
- 如果让你重做一次，你会把哪个任务拆得更小？
