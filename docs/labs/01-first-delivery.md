# 实验 01 · 第一次交付

<LessonMeta level="入门" minutes="45" prerequisite="Claude Code 实操、Git 最小必要技能" output="一个可运行页面、一次提交、一条实验记录" />

## 一句话理解

**这一次，你不是看 AI 写代码，而是完整走一遍：说需求 → 看计划 → 让它做 → 自己验收 → 存档。**

## 目标

在空目录里做一个「今日待办」单页应用：

- 可以添加待办；
- 可以勾选完成；
- 可以删除；
- 刷新后数据还在；
- 手机上看不溢出。

## 开始前检查

- [ ] 已经安装 Claude Code，`claude --version` 有输出。
- [ ] 已经安装 Git，`git --version` 有输出。
- [ ] 准备在临时目录里练习，不使用真实数据。

## 步骤

### 第 1 步：建立目录和基线

```bash
mkdir -p ~/vibe-lab/todo-app
cd ~/vibe-lab/todo-app
git init
```

创建 `README.md`，写一句项目说明，然后提交：

```bash
git add README.md
git commit -m "chore: initial baseline"
```

### 第 2 步：先写验收标准

把下面这段保存下来，等会儿一起发给 AI：

```text
验收标准：
1. 输入内容后点击添加，列表新增一条，输入框清空
2. 空内容不能添加
3. 勾选后条目显示完成样式，再次点击可取消
4. 点击删除后条目消失
5. 刷新页面后，列表和完成状态保持不变
6. 页面宽度 375px 时布局不溢出
```

### 第 3 步：让 AI 先给计划

启动 Claude Code：

```bash
claude
```

把需求和验收标准发给它，并加上一句：

> 先不要写代码。告诉我你准备创建哪些文件、分几步实现、每一步怎么验证。

检查它的计划有没有覆盖：

- 数据存在哪里；
- 添加、勾选、删除三个动作；
- 空输入和保存失败怎么办；
- 刷新后怎么保持数据。

计划不合理，就先改计划。

### 第 4 步：分三步做

建议按顺序提交三次：

1. 先做静态页面和列表显示；
2. 再做添加、勾选、删除；
3. 最后做本地保存和错误处理。

每完成一步，自己打开页面检查，不要等全部做完再验收。

### 第 5 步：自己验收

逐条检查六条验收标准。不要只问 AI「做好了吗」。

### 第 6 步：存档和记录

```bash
git add .
git commit -m "feat: complete todo app"
git log --oneline
```

把过程写进[学习日志](/log/)。

## 验收清单

- [ ] 六条验收标准全部通过。
- [ ] 至少有两个提交，每个提交对应一个能验证的阶段。
- [ ] 能说清 `git diff` 中每一处主要改动的作用。
- [ ] 实验记录写了「卡住的地方」和「下次改进」。
- [ ] 实验目录之外没有产生副作用。

## 卡住了怎么办

| 现象 | 先做什么 |
| --- | --- |
| 页面打不开 | 确认文件路径；直接双击 `index.html`，或启动本地服务 |
| 添加后刷新就没了 | 检查数据有没有保存到 localStorage |
| 手机上布局溢出 | 把验收标准里的 375px 发给 AI，让它只修这一项 |
| AI 一次改太多 | 让它暂停，先只完成第 1 步 |
| 不知道怎么验收 | 把六条验收标准逐条复制出来，做一条勾一条 |

## 复盘问题

- 你在哪一步最想跳过验收？为什么？
- AI 的计划和你预期的一致吗？不一致时谁更合理？
- 如果重做一次，你会把哪个任务拆得更小？
