# 实验 02 · 给项目写 CLAUDE.md

<LessonMeta level="入门" minutes="30" prerequisite="Claude Code 实操" output="一份 80 行以内的 CLAUDE.md" />

## 一句话理解

**这次你要给 AI 写一份「入职手册」，然后观察它是不是真的按手册做事。**

## 目标

体验三个步骤：

1. 让 Claude 自动生成初稿；
2. 你手动删减；
3. 用一个新会话验证规则是否生效。

## 准备

选一个你熟悉的项目。它最好满足：

- 有明确的安装、运行或测试命令；
- 至少有一条项目特有的规矩；
- 工作区是干净的，或者你愿意接受改动。

## 步骤

### 第 1 步：生成初稿

在项目根目录启动 Claude Code，运行：

```text
/init
```

查看生成的 `CLAUDE.md`，数一数有多少行。

### 第 2 步：逐条删减

对每一行问：

> 删掉它，AI 会不会更容易犯错？

优先删掉：

- 读代码就能知道的结构描述；
- 通用语言规范；
- 长篇架构说明；
- 已经过时的命令。

### 第 3 步：补上三类信息

- **能直接执行的命令**：安装、开发、测试、构建；
- **禁止事项**：不能改的目录、不能提交的文件、不能引入的依赖；
- **已知坑**：环境变量、路径、测试数据库等。

### 第 4 步：控制长度

把文件压到 80 行以内。超过时，把细节移到其他文档，并在 CLAUDE.md 里留下链接。

### 第 5 步：验证行为

开一个新的 Claude Code 会话，让它完成一个小任务。观察：

- 它有没有使用正确的测试命令？
- 它有没有避开禁止修改的目录？
- 它有没有踩你写下的坑？

如果没有遵守，先检查规则写得是否具体，而不是继续加规则。

## 验收清单

- [ ] `CLAUDE.md` 在 80 行以内。
- [ ] 包含至少三条可以直接执行的命令。
- [ ] 包含至少两条禁止事项。
- [ ] 包含至少一个项目特有的坑。
- [ ] 在一个新会话中验证过规则是否生效。
- [ ] 文件已纳入 Git。

## 对比实验

把精简前后的两个版本，分别用于两次相似任务，记录：

| 指标 | 精简前 | 精简后 |
| --- | --- | --- |
| 首次回答是否提到正确命令 | | |
| 是否触犯禁止事项 | | |
| 需要你纠正的次数 | | |

不要求差异很大，重点是建立「用行为验证规则」的习惯。

## 卡住了怎么办

- **不知道删什么**：先删「读代码就能知道」的部分。
- **不知道写什么禁止事项**：回想 AI 曾经改坏过什么。
- **规则没生效**：把「注意安全」改成「不要读取 `.env`」这种具体说法。
- **文件还是太长**：把细节移到 `docs/`，只留一句链接。
