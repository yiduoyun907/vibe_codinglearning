# 实验 02 · 给项目写 CLAUDE.md

<LessonMeta level="入门" minutes="30" prerequisite="Claude Code 实操" output="一份 80 行以内的 CLAUDE.md" />

## 目标

体验「自动生成 → 人工精简 → 行为验证」的完整过程，理解为什么短文件比长文件更有效。

## 准备

选一个你熟悉的真实项目，确保：

- 有明确的启动和测试命令；
- 有至少一条项目特有的约定或坑；
- 工作区是干净的，或者你愿意接受改动。

## 步骤

### 1. 生成初稿

在项目根目录启动 Claude Code，运行：

```text
/init
```

查看生成的 `CLAUDE.md`，统计行数。

### 2. 逐条删减

对每一行问：**删掉它，AI 会不会更容易犯错？**

优先删除：

- 读代码就能知道的结构描述；
- 通用语言规范；
- 长篇架构说明；
- 过时的命令。

### 3. 补上三类信息

- **可执行命令**：安装、开发、测试、构建；
- **禁止事项**：不能改的目录、不能提交的文件、不能引入的依赖；
- **已知坑**：环境变量、路径、测试数据库等。

### 4. 控制长度

把文件压缩到 80 行以内。如果超过，把细节移到其他文档，并在 CLAUDE.md 中留下链接。

### 5. 验证行为

开一个新的 Claude Code 会话，让它完成一个小任务。观察：

- 它有没有使用正确的测试命令？
- 它有没有避开禁止修改的目录？
- 它有没有踩你写下的坑？

如果没有遵守，先检查规则表述是否明确，而不是继续增加规则。

## 验收清单

- [ ] `CLAUDE.md` 在 80 行以内。
- [ ] 包含至少三条可直接执行的命令。
- [ ] 包含至少两条禁止事项。
- [ ] 包含至少一个项目特有的坑。
- [ ] 在一个新会话中验证过规则是否生效。
- [ ] 文件已纳入 Git。

## 对比实验

把精简前后的两个版本分别用于两次相似任务，记录：

| 指标 | 精简前 | 精简后 |
| --- | --- | --- |
| 首次回答是否提到正确命令 | | |
| 是否触犯禁止事项 | | |
| 需要你纠正的次数 | | |

结论不必追求显著差异，重点是建立「用行为验证规则」的习惯。
