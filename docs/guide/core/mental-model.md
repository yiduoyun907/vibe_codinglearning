# 心智模型：从意图到交付

<LessonMeta level="入门" minutes="20" prerequisite="Vibe Coding 是什么，不是什么" output="一张四行任务卡" />

## 学习目标

学完这一课，你应该能：

- 把一次 AI 协作为拆成四步：意图、规格、执行、验收。
- 判断一次失败发生在哪一步。
- 把任务切小，小到你能判断对错。

## 一句话理解

**把 AI 协作想成点菜：你说清想吃什么，写清做法，厨师做，你试吃。**

| 点菜 | AI 协作 | 谁负责 |
| --- | --- | --- |
| 我想吃一碗不辣的面 | 意图 | 你 |
| 少盐、不要香菜、面煮软一点 | 规格 | 你 |
| 厨师下厨 | 执行 | AI |
| 你尝一口，判断能不能上桌 | 验收 | 你 |

## 核心概念

### 1. 四步框架

| 步骤 | 你要回答的问题 | 如果这一步没做好 |
| --- | --- | --- |
| 意图 | 我要解决什么问题？为谁解决？ | 做出来的东西不是你要的 |
| 规格 | 做成什么样算完成？怎么验证？ | AI 理解对了，但方向跑偏 |
| 执行 | 让 AI 写或改代码 | 代码能跑，但结构或边界有问题 |
| 验收 | 结果真的符合规格吗？ | 问题被带进下一轮，越积越多 |

大多数「AI 不好用」的抱怨，问题出在前两步，而不是模型不够聪明。

::: details 证据卡｜Anthropic Claude Code 官方工作流
- **来源类型**：官方文档
- **支持什么**：先计划、写项目说明（CLAUDE.md）、管理上下文、修改后验证，是官方推荐的工作方式
- **适用边界**：厂商文档，工具相关；具体命令会随版本变化
- **对本站的含义**：四步框架与主流 AI 编程工具的工作流一致
:::

### 2. AI 是执行者，不是决策者

AI 可以帮你：

- 把明确的要求翻译成代码；
- 提出几种实现方案；
- 提醒你没想到的边界情况；
- 解释报错和代码行为。

AI 不应该替你决定：

- 产品要解决什么问题；
- 哪些取舍可以接受；
- 什么算「完成」；
- 哪些数据可以碰、哪些不能。

::: tip 一个简单的分工
**你负责「做什么、为什么、算不算完成」，AI 负责「怎么写、先写哪一步」。**
:::

### 3. 一次只改一个能验证的点

把任务切小，不是为了照顾 AI，而是为了照顾你自己。

一个合格的改动单元满足：

- 只解决一个问题；
- 有明确的输入和预期结果；
- 能单独运行或检查；
- 失败时可以单独撤销。

| 不推荐 | 推荐 |
| --- | --- |
| 帮我做一个用户系统 | 给现有登录接口加「连续失败五次锁定十分钟」，并写测试 |
| 把页面做得好看一点 | 把首页标题字号改成 32px，按钮间距改成 12px |
| 修一下所有 bug | 先修「空输入会导致页面崩溃」这一个问题 |

::: details 证据卡｜DORA 2025：小批量更容易获得 AI 收益
- **来源类型**：行业调查
- **支持什么**：小批量交付、强版本控制、清晰流程，能让 AI 的收益更容易落地
- **适用边界**：面向团队和组织，相关而非因果
- **对本站的含义**：小步修改不只是学习技巧，也是工程实践
:::

### 4. 上下文是 AI 的工作记忆

AI 不会自动记得你上一个会话说过什么。它这次能看到的，包括：

- 工具预先写好的规则；
- 你们当前的对话；
- 你明确引用的文件；
- 命令输出和报错信息。

所以，「AI 忘了」通常不是它失忆，而是你没有把关键信息放到它面前。

::: details 准确地说
模型没有跨会话的长期记忆。所谓「记忆」，通常是通过项目说明文件（如 CLAUDE.md）、显式引用和会话历史提供的上下文。
:::

### 5. 为什么本站先给范例，再让你动手

对完全没有经验的人来说，纯靠自己摸索并不是最高效的学习方式。先看一个清楚的范例，再做一个类似的小任务，通常更容易建立正确的心智模型。

::: details 证据卡｜新手更需要指导式教学
- **来源类型**：教育研究
- **支持什么**：Kirschner、Sweller、Clark（2006）认为，对新手而言，最少指导式的发现学习效果较差；Rosenshine（2012）总结了小步骤、范例、提问和形成性评价等有效教学原则
- **适用边界**：一般教育研究，不是 AI 专属；高水平学习者可能需要更多自主探索
- **对本站的含义**：课程先给结构、范例和验收标准，再逐步增加你的自主空间
:::

## 动手任务

选一个你正在做或想做的任务，填完下面四行：

```text
意图：我要为____解决____问题，成功的标志是____。
规格：输入是____，输出是____，限制是____，验收方式是____。
执行：我准备让 AI 先做的最小改动是____。
验收：我会通过____来确认它是对的。
```

如果有一行写不出来，先把那一行补上，不要急着让 AI 写代码。

## 验收清单

- [ ] 能用自己的话解释四步框架。
- [ ] 能判断一次失败发生在哪一步。
- [ ] 能把一个模糊需求切小到「一次只改一处」。
- [ ] 能说出至少三个必须由你决定、不能交给 AI 的问题。
- [ ] 写出的验收方式能通过「看、点、运行」确认。

## 卡住了怎么办

- **不知道意图怎么写**：先写「谁在什么情况下，想完成什么」。
- **不知道规格怎么写**：先写「我怎么知道它做对了」，再倒推需要什么行为。
- **任务切不小**：问自己「能不能先做一个只显示假数据的最小版本」。
- **AI 总是不按你说的做**：检查你是不是把关键限制写进了当前对话或 CLAUDE.md。

## 常见误解

- **把 AI 当搜索引擎**：搜索给你资料，AI 给你「看起来合理的答案」。后者更需要验证。
- **一次描述十个需求**：AI 会挑容易的做，或者做出一个四不像。
- **不验收就继续**：错误会进入下一轮，后面的修改都建立在错误基础上。
- **期待 AI 猜你的隐含需求**：没有写出来的限制，AI 大概率不会遵守。
- **认为「提示词写得好」就够了**：规格、上下文和验收同样重要。
