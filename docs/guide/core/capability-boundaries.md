# 能力边界与风险

<LessonMeta level="入门" minutes="20" prerequisite="心智模型：从意图到交付" output="一份自己的任务风险判断清单" />

## 学习目标

学完这一课，你应该能：

- 快速判断一个任务适合交给 AI 的程度。
- 认出 AI 编程中最常见的几类风险。
- 用四个问题决定：这件事要检查到什么程度。

## 一句话理解

**AI 很会写「看起来对」的代码，但「到底对不对」要由你判断。**

## 核心概念

### 1. AI 比较擅长的任务

- **重复、有固定套路的代码**：表单、列表、增删改查、数据转换。
- **输入输出明确的函数**：解析、格式化、校验。
- **重构和批量修改**：在有测试保护的前提下，改名、拆模块、替换写法。
- **测试初稿**：根据现有行为生成测试，再由你补充边界情况。
- **陌生工具的入门示例**：快速得到一个能跑的最小例子。
- **解释和排查**：读报错、解释代码、给出排查方向。

这些任务的共同点：**结果容易验证，出错代价可控。**

### 2. AI 相对不擅长的任务

- **模糊需求**：你越模糊，它越会「合理发挥」。
- **业务规则**：财务口径、医疗逻辑、法律条款，错得很自信。
- **安全关键代码**：登录、鉴权、支付、权限边界。
- **长期架构**：它擅长局部最优，不擅长为两年后的维护做取舍。
- **性能优化**：没有真实测量数据的优化，多半是猜测。
- **需要真实反馈的事**：用户研究、产品取舍、团队协作。

这些任务的共同点：**对错不只看代码，出错代价高。**

### 3. 六类常见风险

| 风险 | 用大白话说 | 怎么防 |
| --- | --- | --- |
| 幻觉 | 编造一个不存在的函数、参数或配置 | 对照官方文档和类型定义 |
| 静默改行为 | 主流程正常，但边角行为被悄悄改了 | 看 diff，补测试 |
| 依赖膨胀 | 为一个小功能引入一个大依赖 | 检查依赖变更，优先用现有能力 |
| 安全漏洞 | 拼接 SQL、放宽权限、把密钥写死 | 安全审查，密钥不进对话 |
| 隐私泄露 | 把真实数据、日志、密钥贴进上下文 | 脱敏，使用假数据 |
| 许可问题 | 复制了来源不明的代码 | 审查来源，保留许可信息 |

::: danger 一条硬规则
**密钥、Token、生产数据库连接串、真实用户数据，永远不要贴进 AI 对话。**

需要上下文时，用脱敏样例和结构说明代替。
:::

### 4. 四个判断问题

给一个任务打分时，问自己：

1. **能验证吗**：结果能不能通过运行、测试或明确检查来确认？
2. **能撤销吗**：出错后能不能快速回到之前的状态？
3. **影响多大**：只影响一个页面，还是影响所有用户和数据？
4. **数据敏感吗**：是否涉及密钥、个人信息、生产数据？

判断规则：

- 四项都友好 → 可以放手，重点看结果。
- 有一项不友好 → 提高检查强度。
- 两项以上不友好，或涉及安全和真实数据 → 必须逐行检查，必要时自己写。

## 验收清单

- [ ] 能说出至少三类 AI 比较擅长的任务。
- [ ] 能说出至少三类必须自己把关的任务。
- [ ] 能用四个问题给任务打分，并解释结论。
- [ ] 明确知道哪些数据绝对不能进入 AI 对话。

## 卡住了怎么办

- **不知道任务风险高不高**：先问「最坏会怎样」。如果会泄露数据、影响真实用户或无法撤销，就按高风险处理。
- **拿不准某个 API 是否存在**：让 AI 给出官方文档链接，或自己查一遍。
- **分不清「能运行」和「正确」**：写下三条验收标准，再逐条运行验证。

## 常见误解

- **「它能写，就说明它写对了」**：能写只代表模型生成得出来，不代表符合事实或需求。
- **「安全代码和普通代码差不多」**：鉴权、支付、权限边界需要专门审查。
- **「只看新增代码就够了」**：静默行为变化往往藏在被修改或删除的行里。
- **「累了就快速点通过」**：疲劳时更容易漏掉问题。宁可不改，也不要盲审。
