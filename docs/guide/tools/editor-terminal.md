# 编辑器与终端

<LessonMeta level="入门" minutes="25" prerequisite="Claude Code 实操" output="一个可运行、可编辑、可验证的项目环境" />

## 学习目标

学完这一课，你应该能：

- 在终端里进入目录、创建文件夹、启动本地服务。
- 用编辑器查看和修改文件，并看懂改动。
- 建立一个结构清晰的最小项目。

## 一句话理解

**终端是用打字给电脑下命令，编辑器是用来看和改文件。** 两个配合起来，你就能自己检查 AI 到底改了什么。

## 核心概念

### 1. 终端：不用鼠标，用文字操作

你只需要先记住这几条：

| 目的 | 命令 | 例子 |
| --- | --- | --- |
| 看我在哪个文件夹 | `pwd` | `pwd` |
| 列出文件 | `ls`（Git Bash）或 `dir`（PowerShell） | `ls` |
| 进入文件夹 | `cd 文件夹名` | `cd vibe-lab` |
| 回到上一级 | `cd ..` | `cd ..` |
| 创建文件夹 | `mkdir 文件夹名` | `mkdir demo` |
| 用编辑器打开当前文件夹 | `code .` | `code .` |
| 启动本地网页服务 | `python -m http.server 8000` | 然后在浏览器打开 `localhost:8000` |
| 停止正在运行的程序 | `Ctrl+C` | 在终端里按 |

::: tip 路径里有空格
路径含空格时，用引号包起来：

```bash
cd "C:\My Projects\demo"
```

这是 Windows 上最常见的「命令找不到」原因之一。
:::

### 2. 编辑器：用来看和改

推荐 VS Code，也可以用 Cursor 等编辑器。你最常用的三个区域是：

- **文件列表**：项目里有哪些文件。
- **编辑区**：看和改代码。
- **源代码管理 / diff**：看 AI 改了哪几行。

```text
┌─────────────┬──────────────────────────┐
│ 文件列表     │ 编辑区                    │
│             │                          │
│             │                          │
├─────────────┴──────────────────────────┤
│ 终端 / 问题 / 输出                       │
└────────────────────────────────────────┘
```

> 布局示意，实际界面以你安装的版本为准。

### 3. 最小项目结构

一个让 AI 和你都容易理解的项目，至少有这些文件：

```text
hello-env/
├── .gitignore        # 告诉 Git 哪些文件不用管
├── README.md         # 项目是什么、怎么运行
├── CLAUDE.md         # 给 AI 的项目说明
├── index.html        # 网页入口
└── src/              # 源码
```

不需要一开始就上复杂框架。**结构清楚，比技术先进更重要。**

### 4. 修改后怎么验证

每次改完，按这个顺序检查：

1. 终端有没有报错？
2. 浏览器能不能打开？
3. 关键按钮和行为对不对？
4. 回到 diff，确认只改了预期的地方。

## 动手任务

### 第 1 步：建立目录

```bash
mkdir -p ~/vibe-lab/hello-env
cd ~/vibe-lab/hello-env
```

### 第 2 步：打开编辑器

```bash
code .
```

### 第 3 步：创建页面

新建 `index.html`，写入下面内容。可以自己写，也可以让 Claude 写：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>我的第一个页面</title>
  </head>
  <body>
    <h1>你好，Vibe Coding</h1>
    <p>这是我亲手启动的页面。</p>
  </body>
</html>
```

### 第 4 步：启动本地服务

```bash
python -m http.server 8000
```

浏览器打开 `http://localhost:8000`，确认页面显示正常。

### 第 5 步：改一处，再刷新

把标题改成「我改了标题」，保存，刷新浏览器，观察变化。

### 第 6 步：停止服务

回到终端，按 `Ctrl+C`。

## 验收清单

- [ ] 能独立进入目录、创建文件夹、启动本地服务。
- [ ] 知道怎么停止一个正在运行的程序。
- [ ] 能在编辑器里看到文件改动。
- [ ] 项目里有 README、.gitignore 和清晰的入口文件。
- [ ] 完成过一次「修改 → 刷新 → 验证 → 停止」。

## 卡住了怎么办

| 现象 | 先检查 |
| --- | --- |
| 提示命令不存在 | 是否装了这个工具；是否在正确的终端里；重启终端试试 |
| 页面打不开 | 服务是否还在运行；地址和端口是否写对 |
| 端口被占用 | 换一个端口，例如 `8000` 改成 `8001` |
| 改完没变化 | 是否保存；浏览器是否缓存（强制刷新试试） |
| 路径报错 | 是否在正确的目录；路径有空格是否加了引号 |

## 常见误解

- **「终端很危险」**：危险的是不看清命令就执行的高风险操作，不是终端本身。
- **「编辑器越复杂越好」**：先用好文件列表、编辑区和 diff 三个功能。
- **「本地能打开，别人也能打开」**：`localhost` 只对你自己的电脑有效。
- **「改完文件就自动生效」**：静态页面要刷新；有些项目需要重新构建或重启服务。
