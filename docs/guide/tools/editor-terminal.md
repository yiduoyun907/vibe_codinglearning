# 编辑器与终端

<LessonMeta level="入门" minutes="25" prerequisite="Claude Code 实操" output="一个可运行、可编辑、可验证的项目环境" />

## 学习目标

学完这一课，你应该能：

- 在终端里完成定位目录、创建文件、启动本地服务。
- 用编辑器的 diff 视图审查 AI 的改动。
- 建立一个最小项目结构，让 AI 和你都能快速理解。

## 核心概念

### 1. 终端是控制面

Claude Code 在终端里工作。你不需要成为终端专家，但必须掌握下面这些动作：

| 目的 | 命令（Windows PowerShell / Git Bash） |
| --- | --- |
| 查看当前目录 | `pwd` |
| 列出文件 | `ls`（Git Bash）或 `dir`（PowerShell） |
| 进入目录 | `cd 路径` |
| 创建目录 | `mkdir 目录名` |
| 用编辑器打开当前目录 | `code .` |
| 启动本地静态服务器 | `python -m http.server 8000` |
| 停止正在运行的命令 | `Ctrl+C` |

::: tip 路径里有空格
路径含空格时用引号包起来，例如 `cd "C:\My Projects\demo"`。这是 Windows 上最常见的「命令找不到」原因之一。
:::

### 2. 编辑器负责审查

推荐 VS Code 或支持 Claude Code 扩展的编辑器。你最常用的三个能力是：

- **集成终端**：不用在窗口之间来回切换。
- **源代码管理面板**：直观看到哪些文件被改、改了什么。
- **Diff 视图**：逐块审查 AI 的修改，而不是只看最终文件。

Cursor 等编辑器也可以使用，但不要同时装多个功能重叠的 AI 插件。工具冲突时，你很难判断是谁改的。

### 3. 最小项目结构

一个让 AI 容易理解的项目，至少有这些文件：

```text
hello-claude/
├── .gitignore        # 排除 node_modules、构建产物、密钥
├── README.md         # 项目是什么、怎么运行
├── CLAUDE.md         # 给 AI 的项目约定
├── index.html        # 入口文件
└── src/              # 源码
```

不需要一开始就上复杂框架。**结构清晰比技术栈先进更重要。**

### 4. 一次完整的本地验证

改完代码后，验证顺序建议是：

1. 看终端有没有报错；
2. 打开浏览器或运行测试；
3. 检查关键交互，而不只是页面能不能加载；
4. 回到 diff，确认改动范围符合预期。

## 动手任务

1. 打开终端，创建实验目录：

   ```bash
   mkdir -p ~/vibe-lab/hello-env
   cd ~/vibe-lab/hello-env
   ```

2. 用编辑器打开：

   ```bash
   code .
   ```

3. 创建 `index.html`，写一个最小页面（可以自己写，也可以让 Claude 写）。
4. 启动本地服务：

   ```bash
   python -m http.server 8000
   ```

5. 浏览器访问 `http://localhost:8000`，确认页面正常。
6. 修改标题，刷新页面，观察变化。
7. 在终端按 `Ctrl+C` 停止服务。

## 验收清单

- [ ] 能独立在终端里定位目录、创建目录、启动本地服务。
- [ ] 知道如何停止一个正在运行的命令。
- [ ] 能在编辑器里看到文件改动并打开 diff。
- [ ] 项目里有 README、.gitignore 和清晰的入口文件。
- [ ] 完成过一次「修改 → 刷新 → 验证 → 停止服务」。

## 常见坑

- **在错误的目录里运行命令**：先 `pwd` 确认位置，再执行。
- **忘记停止服务**：端口被占用时，先找到并结束旧进程。
- **直接编辑 `node_modules` 或构建产物**：这些文件会被覆盖，改动应该回到源码。
- **路径含空格不加引号**：命令会被拆成两段。
- **同时开多个 AI 工具改同一个文件**：冲突和覆盖很难排查。
