# MCP 与工具扩展

<LessonMeta level="进阶" minutes="25" prerequisite="Claude Code 实操" output="一份 MCP 服务器评估结论" />

## 学习目标

学完这一课，你应该能：

- 解释 MCP 是什么，以及它解决什么问题。
- 判断一个需求是否需要 MCP，而不是默认「装一个」。
- 用安全清单评估一个 MCP 服务器是否值得接入。

## 核心概念

### 1. MCP 是什么

MCP（Model Context Protocol）是一个开放协议，用来把 AI 客户端连接到外部工具和数据源。你可以把它理解成「AI 世界的 USB 接口」：

- **客户端**：Claude Code 等 AI 工具；
- **服务器**：暴露工具、资源或提示的进程；
- **工具调用**：客户端把服务器的能力提供给模型，模型按需调用。

没有 MCP 时，AI 只能通过终端命令和文件读写间接操作外部系统；有了 MCP，它可以以结构化方式访问 GitHub、浏览器、数据库、文档系统等。

### 2. 什么时候真正需要

适合接入：

- 需要频繁操作外部系统，例如查询 issue、读取知识库、操作浏览器；
- 需要结构化数据，而不是让 AI 解析命令输出；
- 需要把团队内部的只读数据源提供给它。

不需要接入：

- 只是读写本地文件；
- 只是运行几条 shell 命令；
- 只是想让它查一次网页。

::: tip 先问三个问题
1. 现有工具能不能完成？
2. 这个服务器需要访问什么数据？
3. 最坏情况下，它能造成什么影响？
:::

### 3. 接入方式

Claude Code 使用 `claude mcp add` 管理服务器。以 Playwright 浏览器服务器为例：

```bash
claude mcp add playwright -- npx -y @playwright/mcp@latest
claude mcp list
```

在会话内可以用 `/mcp` 查看和管理已接入的服务器。

作用域有三种：

| 作用域 | 存储位置 | 适用场景 |
| --- | --- | --- |
| `local`（默认） | 当前项目的本地配置 | 个人临时实验 |
| `project` | 项目根目录 `.mcp.json` | 团队共享 |
| `user` | 用户级配置 | 所有项目都要用 |

项目级配置写在仓库根目录的 `.mcp.json`，结构如下：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```

### 4. 安全边界

MCP 服务器本质上是在你的机器上运行的程序，或者代表你访问外部系统的服务。接入前至少检查：

- **来源**：作者、仓库、发布记录是否可信？
- **权限**：它需要读取哪些数据？能否改成只读？
- **网络**：它会向哪些地址发请求？
- **写入能力**：能否修改文件、发消息、提交代码？
- **凭据**：Token 如何传入？是否通过环境变量而不是硬编码？

::: danger 外部内容可能携带指令
浏览器、网页、issue 内容都可能包含针对 AI 的恶意指令。接入能读取外部内容的服务器后，不要把「读到的内容」当成可信指令执行。
:::

## 常见坑

- **见一个装一个**：每个服务器都扩大攻击面和上下文负担。
- **给过宽的凭据**：优先使用只读、最小权限的 Token。
- **把 Token 写进 `.mcp.json`**：用环境变量引用，避免提交到仓库。
- **忽略项目级服务器的审批**：`.mcp.json` 中的服务器需要你确认后才会生效。
- **把外部内容当指令**：网页和文档里的文字是数据，不是你的指令。
