# 课程总览

<LessonMeta level="入门到进阶" minutes="约 5 小时" output="完成首批课程并留下可验证的练习记录" prerequisite="无" />

首批课程聚焦三件事：**建立正确认知、跑通工具链、学会写规格**。这三件事决定了后续所有实践的上限。

## 阶段一 · 认知基础

先把「AI 能做什么、不能做什么、我该负责什么」想清楚，再谈效率。

| 课程 | 你带走什么 |
| --- | --- |
| [什么是 Vibe Coding](/guide/core/what-is-vibe-coding) | 一个不神化也不贬低 AI 的准确定义 |
| [心智模型：从意图到交付](/guide/core/mental-model) | 意图、规格、执行、验收四层框架 |
| [能力边界与风险](/guide/core/capability-boundaries) | 一份「可以交给 AI / 必须自己把关」的判断清单 |

## 阶段二 · 工具链

先把最小工作流跑通，再逐步扩展工具，避免一开始就陷入配置。

| 课程 | 你带走什么 |
| --- | --- |
| [Claude Code 实操](/guide/tools/claude-code) | 安装、权限、CLAUDE.md、常用工作流 |
| [编辑器与终端](/guide/tools/editor-terminal) | 支撑 AI 协作的最小环境 |
| [Git 最小必要技能](/guide/tools/git-basics) | 审查、提交、回滚 AI 改动的能力 |
| [MCP 与工具扩展](/guide/tools/mcp) | 判断什么时候需要 MCP，以及如何安全接入 |

## 阶段三 · 提示与规格

规格的质量，直接决定 AI 交付的质量。这一阶段的目标不是「会写提示词」，而是「会定义问题」。

| 课程 | 你带走什么 |
| --- | --- |
| [需求拆解](/guide/spec/requirement-decomposition) | 把模糊想法变成可执行任务的方法 |
| [写一份好用的 CLAUDE.md](/guide/spec/claude-md) | 一个可复用的项目上下文模板 |
| [PRD 与 SPEC](/guide/spec/prd-spec) | 让 AI 按验收标准交付的规格模板 |
| [上下文管理](/guide/spec/context-management) | 会话、文件、摘要的管理策略 |

## 每课的结构

所有课程使用同一套结构，便于快速定位：

1. **学习目标**：这一课结束后你能做什么。
2. **核心概念**：不超过五个，避免信息过载。
3. **动手任务**：必须在自己的环境里完成的动作。
4. **验收清单**：判断是否真正掌握的硬标准。
5. **常见坑**：真实使用中最容易出错的地方。
6. **延伸阅读**：想深入时的方向。

## 学习建议

::: tip 以产出为准
读完不算完成。每课底部的「标记本课为已完成」只在你完成动手任务并通过验收清单后再点。
:::

- 一次只学一课，学完立刻在真实项目里用一次。
- 遇到不理解的概念，先做最小实验，再回来读定义。
- 把自己的失败案例写进[反模式库](/anti-patterns/)，比复制成功经验更有价值。
