# 写一份好用的 CLAUDE.md

<LessonMeta level="进阶" minutes="25" prerequisite="Claude Code 实操" output="一份经过精简的项目 CLAUDE.md" />

## 学习目标

学完这一课，你应该能：

- 判断哪些内容应该写进 CLAUDE.md，哪些不应该。
- 用 `/init` 生成初稿，并把它精简到可维护的长度。
- 通过观察 AI 的行为，验证一条规则是否真的有用。

## 一句话理解

**CLAUDE.md 是给 AI 的入职手册：告诉它这个项目怎么跑、有什么规矩、哪些坑不要踩。**

## 核心概念

### 1. 它是什么，放在哪里

`CLAUDE.md` 是每次会话开始时自动加载的项目说明。它可以放在：

| 位置 | 作用 |
| --- | --- |
| 项目根目录 `CLAUDE.md` | 全项目通用规则 |
| 子目录 `CLAUDE.md` | 该目录的局部规则，需要时加载 |
| `~/.claude/CLAUDE.md` | 你个人所有项目的偏好 |

它解决的问题是：**有些信息，AI 光看代码猜不出来。**

例如：

- 测试要用哪个命令；
- 哪个目录是自动生成的，不能手改；
- 本地环境有一个奇怪的坑。

### 2. 该写什么，不该写什么

| 应该写 | 不应该写 |
| --- | --- |
| AI 猜不到的运行、测试命令 | 读代码就能知道的实现细节 |
| 和默认习惯不同的代码风格 | 通用语言规范 |
| 测试方式和偏好 | 长篇 API 文档（给链接） |
| 分支命名、提交规范 | 经常变化的信息 |
| 项目特有的架构决定 | 逐文件描述代码库 |
| 本地环境的坑 | 「写干净的代码」这类空话 |

判断标准只有一句：

> **删掉这一行，AI 会不会更容易犯错？**

如果不会，就删掉。

### 3. 推荐结构

```markdown
# 项目概览

一句话说明这个项目是什么、给谁用。

# 常用命令

- 安装依赖：`npm install`
- 本地开发：`npm run dev`
- 运行测试：`npm test -- <文件>`
- 构建：`npm run build`

# 架构与目录

- `src/`：业务代码
- `src/api/`：接口层，不直接操作数据库
- `docs/`：设计文档

# 代码约定

- 使用 ES modules，不使用 CommonJS
- 组件文件名使用 PascalCase
- 新增依赖前先确认现有依赖能否满足

# 禁止事项

- 不要修改 `src/generated/`，它由代码生成
- 不要提交 `.env` 或任何密钥
- 不要改动已合并的数据库迁移文件，新增迁移代替

# 已知坑

- 测试必须先设置 `NODE_ENV=test`，否则会连接开发数据库
- Windows 上路径使用正斜杠
```

### 4. 短，比全更重要

CLAUDE.md 每次会话都会加载。越长，越容易被忽略。

经验值：

- 控制在 100 行以内；
- 一条规则一行；
- 重要的规则可以单独强调，但不要到处强调；
- 细节放到链接的文档里。

如果 AI 反复违反某条规则，先检查文件是不是太长、规则是不是互相矛盾，而不是继续堆更多规则。

### 5. 让它持续进化

- 用 `/init` 生成初稿；
- 每次 AI 犯错后，问自己：这是不是一条该写进 CLAUDE.md 的规则？
- 定期删除过时或能被代码推断的内容；
- 把 CLAUDE.md 纳入 Git，改动可追溯。

## 动手任务

1. 选一个真实项目，运行 `/init` 生成初稿。
2. 通读初稿，删除所有「读代码就能知道」的内容。
3. 补上三类信息：常用命令、禁止事项、已知坑。
4. 把文件控制在 80 行以内。
5. 开一个新会话，观察 AI 是否遵守约定。如果不遵守，调整表述，而不是加长文件。

## 验收清单

- [ ] CLAUDE.md 包含可执行的命令，而不只是描述。
- [ ] 写明了至少两条禁止事项。
- [ ] 写明了至少一个项目特有的坑。
- [ ] 文件长度控制在 100 行以内。
- [ ] 每条内容都通过了「删掉它会不会让 AI 犯错」的测试。
- [ ] 文件已纳入 Git。

## 卡住了怎么办

- **初稿太长**：先删目录结构描述，再删通用规范，最后删过时命令。
- **不知道写什么禁止事项**：回想一下 AI 曾经改坏过什么。
- **写了规则但 AI 不遵守**：把规则改得更具体，例如把「注意安全」改成「不要读取 `.env`」。
- **多个项目要共用规则**：把通用偏好放到用户级 `~/.claude/CLAUDE.md`，项目特有的放项目根目录。

## 常见误解

- **「写成长篇教程更专业」**：加载成本高，执行效果反而差。
- **「复制网上的最佳实践就行」**：AI 本来就知道的内容不值得占上下文。
- **「写完就不用管了」**：过时规则会误导 AI，需要定期清理。
- **「把临时任务也写进去」**：临时需求放当前对话，不要放进永久上下文。
- **「只写要做什么」**：禁止事项往往更能防止事故。
