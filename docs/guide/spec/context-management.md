# 上下文管理

<LessonMeta level="进阶" minutes="25" prerequisite="Claude Code 实操" output="一次干净的上下文交接" />

## 学习目标

学完这一课，你应该能：

- 识别上下文中三类常见污染。
- 判断什么时候该清理、什么时候该压缩。
- 用一份交接笔记在会话之间传递状态。

## 核心概念

### 1. 上下文是工作记忆

模型每次只能看到有限的内容。占用上下文的包括：

- 系统提示和项目指令；
- 当前对话历史；
- 你引用的文件和粘贴的代码；
- 命令输出、报错和工具结果；
- 模型自己的中间推理和总结。

上下文不是越多越好。无关信息会稀释关键信息，过期信息会误导判断，错误信息会被反复继承。

### 2. 三类污染

| 类型 | 例子 | 后果 |
| --- | --- | --- |
| 无关信息 | 在同一会话里讨论三个不相关的任务 | 模型抓错重点 |
| 过期信息 | 早期方案已废弃，但仍在对话里 | 模型参考旧方案 |
| 错误信息 | 一次失败的尝试没有被标记 | 模型沿着错误路径继续 |

清理上下文的目的，不是「省 token」，而是**保证模型看到的是当前有效的信息**。

### 3. 四种管理动作

| 动作 | 何时用 | 做法 |
| --- | --- | --- |
| 精确引用 | 需要某个文件 | 用 `@文件路径`，不要整段粘贴 |
| 清理 | 切换到不相关任务 | `/clear` |
| 压缩 | 同一任务但历史太长 | `/compact`，保留摘要 |
| 交接 | 需要跨会话继续 | 写一份状态笔记，再开新会话 |

### 4. 写一份交接笔记

清空上下文前，把状态写成一个文件或一段可复制的文本：

```markdown
# 任务交接

## 目标
<这次要实现什么，验收标准是什么>

## 已完成
- <改动 1，对应文件>
- <改动 2，对应文件>

## 当前状态
- 可以运行 / 有报错：<具体报错>
- 已验证：<验证方式与结果>

## 下一步
- <最小下一步动作>

## 约束与禁忌
- <不能改的文件、不能引入的依赖、已知坑>

## 相关文件
- @src/xxx.ts
- @docs/spec.md
```

有了它，新会话不需要重新读完整段历史，也能快速进入状态。

### 5. 把稳定知识移出对话

对话是临时的，项目知识应该是持久的：

- 长期规则 → `CLAUDE.md`
- 功能规格 → `docs/spec/`
- 决策记录 → 简短 ADR 或日志
- 一次性尝试 → 留在当前会话，结束后丢弃

::: tip 一个判断
如果一条信息下周还会用到，就不要只把它留在聊天记录里。
:::

### 6. 控制工具输出的噪音

AI 读文件、跑命令时，输出也会进入上下文。减少噪音的方法：

- 让它先搜索，再读取相关片段，而不是读整个大文件；
- 命令输出加过滤，例如只看错误行或最后几十行；
- 避免读取 `node_modules`、构建产物、日志全量内容；
- 大范围调研可以交给子任务，只把结论带回主会话。

## 动手任务

1. 找一个已经进行很久的 AI 会话。
2. 按上面的模板写一份交接笔记。
3. 执行 `/clear`，用交接笔记作为新会话的第一条消息。
4. 观察新会话是否还需要你重复解释背景。
5. 对比清理前后，AI 的回答质量和速度有什么变化。

## 验收清单

- [ ] 能说出三类上下文污染，并各举一个例子。
- [ ] 知道 `/clear` 和 `/compact` 的适用场景。
- [ ] 能写出一份别人（或新的 AI 会话）看得懂的交接笔记。
- [ ] 会把长期规则放进 CLAUDE.md，而不是依赖对话记忆。
- [ ] 能让 AI 读取目标片段，而不是整个大文件。

## 常见坑

- **把整个仓库贴进对话**：噪音大、成本高、关键信息被淹没。
- **不清理失败尝试**：错误假设会继续影响后续判断。
- **在长会话里反复解释同一件事**：说明信息没有沉淀到持久文件。
- **只压缩不清理**：压缩保留了摘要，但无关任务仍然占空间。
- **依赖 AI 记住决定**：跨会话没有记忆，决定要写下来。
- **让 AI 读构建产物**：既浪费上下文，也可能读到过期代码。
